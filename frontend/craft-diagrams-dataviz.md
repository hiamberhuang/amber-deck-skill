# SVG 图解与数据图表

数值按 1440×810 画布。图解和图表的共同原则只有一条：**形状的每一个尺寸都要有出处**。位置是算出来的，宽度对应数据，间距取自同一把尺。凭感觉摆出来的图解，一眼就能看出线没接上、箭头歪了、间隔不匀。

## 1. 通用几何规则

**1.1 文字用 HTML，线和形状用 SVG。** 节点是 HTML 元素，文字能换行、能被选中、能跑孤字修复；连接线是叠在上面的一层 SVG，端点从节点的实际位置量出来。只有圆环、漏斗、折线这类纯几何图才把文字也写进 SVG。片段：`13-flow.html`。

**1.2 坐标取整到 0.5px。** 1px 的线画在整数坐标上会糊成 2px 的灰线，画在 .5 上才锐利。偶数线宽用整数坐标。

**1.3 箭头是独立的三角形，不用 `marker`。** `marker-end` 的箭头会随线宽缩放，线头会从箭头尖里戳出来，颜色也不好单独控制。做法：

1. 算出线的终点和终点处的方向。
2. 箭头尖停在距离目标节点 6px 的地方。
3. 线段缩短一个箭头的长度，线头藏在箭头底边后面。
4. 箭头长 10–15px，底宽是长的 1 到 1.1 倍，实心填充，颜色和线一致。

**1.4 线的端点只有两种状态。** 要么贴在节点边缘上（0px），要么留出明确的 4–8px 间隙。2–3px 的间隙看起来像没对准。全图统一一种。

**1.5 连接线只走水平和垂直。** 流程图和架构图不用斜线和随意的曲线。拐弯用直角或半径 8px 的圆角。线不穿过节点，不压在文字上，不贴着节点的边走（至少留 16px）。

**1.6 线宽和线型的含义固定。** 主路径实线 1.8px；次要或回流路径虚线（`4 4`）同线宽；轨道、网格这类底线 1px 浅色。一张图里线型不超过两种。

**1.7 节点规则。**

- 一张图不超过 9 个节点，超过就拆成两张或分层。
- 同级节点同宽同高。全图节点尺寸不超过 2–3 种。
- 节点内容：一个标题（2–6 个字）加最多两行说明。节点里不写句号。
- 节点宽度按最长的标题算：字数 × 字号 + 左右各 24px 内边距。
- 只有 1–2 个节点用强调色，就是这页要说的那一步。其余全部中性。

**1.8 SVG 文字的基线。** `<text>` 的 y 是基线位置，不是顶边。在高度 h 的框里垂直居中一行字号为 f 的文字：`y = 框顶 + h/2 + f × 0.35`。两行文字时，标题和说明的基线相差约 1.5 倍小字字号。

**1.9 SVG 里的字体。** `font-family` 中文在前。字号不低于 12px。中文不要用 `textLength` 拉伸。

**1.10 图解不加的东西。** 阴影、渐变、发光、手绘抖动、3D。图解的质感来自精确。

## 2. 闭环（圆上的箭头）

片段：`08-svg-loop.html`。全部用公式算，改节点数只需改数组。

设圆心 (cx, cy)，轨道半径 R，节点半径 r，共 N 个节点。

1. **节点角度**：第 i 个节点在 `θᵢ = −90° + i × 360°/N`。第一个在正上方，顺时针排。节点中心 = `(cx + R·cos θ, cy + R·sin θ)`。
2. **弧线让开节点**：节点在轨道上占的圆心角 `gap = (r + 8) / R`（弧度），其中 8 是线与节点的间隙。第 i 段弧从 `θᵢ + gap` 画到 `θᵢ₊₁ − gap`。
3. **箭头**：尖端在弧的终点；方向是该点的切线，角度 = 该点的半径角 + 90°（顺时针）。弧线的实际终点再往回退一个箭头长对应的角度 `head / R`。
4. **SVG 弧**：`A R R 0 0 1 x y`。N ≥ 3 时每段都小于 180°，large-arc 标志为 0；N = 2 时每段接近 180°，要单独处理。
5. **比例**：r 取 R 的 0.28–0.34。节点直径不小于 4 个汉字宽加 32px。圆心的空位放这个闭环的总结（周期、总量），不要空着，也不要放图标。
6. **强调**：只强调一个节点和一段弧。通常是起点，或者“回流”那一段，因为闭环页要说的就是首尾相接。

## 3. 漏斗

片段：`09-funnel.html`。

1. **宽度就是数据**：每层上边宽 = 本层数值 ÷ 首层数值 × 总宽，下边宽 = 下一层的上边宽。斜边的斜率因此真实反映流失，流失大的一步斜得厉害。
2. **不画等差漏斗**：每层固定缩进一个值的漏斗是装饰，和数据无关。数据画出来不像漏斗（某一步几乎不流失），那就如实画，或者改用条形图。
3. **最小宽度**：末层太窄放不下任何东西时，给绘制宽度设下限（约 64px）。只影响绘制，标注的数字永远是真实值。
4. **标签放外面**：层名和数值在漏斗左侧右对齐成一列；逐层转化率在右侧左对齐成一列，写在两层之间的缝隙高度上。不把字压在梯形里。
5. **层高一致**，层间留 12–16px 缝隙。层数 3–6 层。
6. **颜色**：从上到下同一色相由深到浅；只有标题说的那一步（通常是流失最大的一步的下游层）用强调色，并在右侧多写一句人话（“只有不到一半”）。
7. 标题里的结论必须和图里强调的那一层一致。本片段第一版就犯了这个错：标题说的是第二步，按数据算出来最大流失在第四步，渲染后才发现，改了数据才对上。

## 4. 流程

片段：`13-flow.html`。

1. 主路径一条直线，从左到右（或从上到下），节点等距。分支向下（或向右）偏出一行，用虚线和弱化的节点。
2. 步骤 3–5 个最好，超过 6 个分成两行或改成时间线。
3. 序号只在真的有先后顺序时才写，用小号数字，不用“01 / 02 / 03”这种装饰大号。
4. 节点间的箭头线长度 = 列间距。列间距不小于 48px，否则箭头太短像个符号。
5. 回流线从分支节点出发，走到目标节点正下方再向上，全程直角。
6. 强调的节点用强调色实底白字，其余是白卡。分支节点用浅底虚线框，表示“例外情况”。

## 5. 前后对比与方案对比

**5.1 数值的前后对比**（`14-before-after.html`）：

- 每个指标一行，前后两根条上下紧挨，共用一个零点和一把尺。
- “前”用细的中性灰条，“后”用粗的强调色条。颜色只表示前和后这两个含义。
- 变化量单独一列，右对齐。“越小越好”的指标要写明，否则读者会把条变短理解成变差。
- 各行之间用一条浅线分隔，不用卡片。

**5.2 做法的前后对比 / 方案对比**（`10-comparison.html`）：

- 左右两栏的条目一一对应，行高相同，同一行的内容水平对齐。对不齐就不叫对比。
- 弱的一侧融进背景：浅底、无阴影、灰字、常规字重。强的一侧是全页唯一的白卡加阴影，可以上下各高出 18px。
- 强调色只出现在强的一侧，一到两处。
- 行标签（“分配”“首次响应”）在两侧重复出现是可以的，它们是读者横向比较的锚点。

## 6. 时间线

片段：`23-timeline.html`。

1. **x 坐标按时间比例换算**，不平均分。间隔三周和间隔六周看起来必须不一样。
2. 状态三种：已完成（实心深色）、当前或重点（强调色、放大）、未来（空心）。主轴线在“今天”之前是深色，之后是浅色。
3. 标签上下交错，避免相邻标签相撞。首尾两个标签分别左对齐和右对齐，不要居中后伸出画布。
4. 每个节点三行：日期（小、灰）、事件（大、粗）、一句说明。
5. 节点超过 7 个就分段，或者改成按阶段分组的横条。

## 7. 矩阵

片段：`25-matrix.html`。

1. 一个大容器加一横一竖两条线，不是四张卡片。
2. 两条轴都要标两端的含义，标在容器外。纵轴的中文直排（`writing-mode:vertical-rl`），不旋转。
3. 重点象限换底色（强调色实底，或 8% 的强调色浅底），其余透明。
4. 象限里的内容靠下对齐，上方留给数字或图标，四个象限的文字基线才能对齐。

## 8. 数据图表

**8.1 先选对图。**

| 要说的关系 | 用 | 不用 |
|---|---|---|
| 一个数有多大 | 大数字加参照条（`11`） | 仪表盘、进度环 |
| 几项比大小 | 横向条形，降序（`15`） | 饼图、雷达图 |
| 随时间变化 | 折线，最多三条（`16`） | 堆叠面积、双 y 轴 |
| 前后变化 | 成对条形（`14`） | 两个饼图 |
| 构成占比 | 一根分段条，或“每 10 个里有 N 个”的点阵 | 超过 5 块的饼图、3D 饼图 |
| 多行多列的精确值 | 表格（`17`） | 把表格截图贴进来 |
| 逐级流失 | 漏斗（`09`） | 等差漏斗 |

**8.2 标题写结论。** “小红书带来的线索，比其他渠道加起来还多”，不是“线索来源分布”。图里强调的那一个元素，就是标题里说的那件事。

**8.3 只亮一个。** 全图只有一个系列或一根条用强调色，其余用同一档中性灰。需要区分多个系列时用深浅不同的灰，不引入第二种彩色。

**8.4 直接标注，去掉图例和坐标轴。**

- 条形图：数值写在条尾，类别名写在条左侧右对齐。不画数值轴、刻度和网格。
- 折线图：系列名写在线的末端。y 轴只留 3–4 条浅网格线和刻度数字，单位写在左上角一次。
- 起点和终点的数值直接标在点上。
- 关键事件用一条竖虚线加一句话标在图里。

**8.5 条形图从零开始。** 截断 y 轴会夸大差异。条的粗细与间隙之比约 1 : 1.2。圆角只加在条尾，2–3px。

**8.6 折线图。** 主线 3px 强调色，对照线 2px 灰。不加数据点标记，只在末端（和需要强调的转折点）画一个点。不用平滑曲线，除非数据本身是连续采样的。

**8.7 表格。**

- 只留横线：表头下一条较深的线，行间浅线，没有竖线和外框。
- 文字列左对齐，数字列右对齐，表头跟着列对齐。
- 数字用等宽数字和西文字体，小数位统一。
- 行高 64–86px（演示用的表格比文档里的松得多）。一张表不超过 7 行 6 列，超过就只展示最关键的行，其余进附录。
- 重点行用 8% 的强调色浅底，向版心两侧各出血一点；只有这一行的关键数字用强调色。
- 第一列是行名，用粗体。

**8.8 每张图都要有口径和来源。** 一行小字写在图的左下：统计范围、时间、数据源。示意性的数字必须标“示意”。

**8.9 图表里的文字也要过对比度。** 坐标轴数字、来源说明不低于 4.5:1。浅灰的刻度数字是最常见的不达标项，`deck-lint.js` 会检查 SVG 里的 `text`。

**8.10 不用图表库的默认输出。** 演示里的图表数据点很少，用 HTML/CSS 或手写 SVG 就能做，尺寸和字体都跟着令牌走。图表库默认的配色、图例、网格和工具提示都是给交互式仪表盘设计的，搬到幻灯片上就是多余的噪声。数据量确实大时可以用库，但要关掉图例、网格、动画，并把字体和颜色全部换成令牌。
