# HTML 交付与动效

默认交付可在浏览器打开的 HTML 和源码；只有明确要求 PowerPoint / .pptx 时，才走 PPTX 路线。

| 输出 | 优先做法 | 必查 |
|---|---|---|
| 固定尺寸 HTML | 先定 16:9 舞台并设计缩放；用 CSS/WAAPI 或 GSAP timeline，交付本地资产 | 离线无网、首尾导航、深链、键盘、回退、移动端或明确支持范围 |
| 现场大屏 | 全屏、黑屏、重播、暂停、背景声与独立状态；单机离线方案和静态备份 | 投影设备演练；音频手势解锁，讲者优先；QR 和视频实测 |
| PDF / 静态图 | 每页可读终态，保留来源；用于审阅和兜底 | 页数、裁切、字体、链接、信息不靠动画传递 |
| 可编辑 PPTX | 现有母版或本机可用的 PPTX skill；原生文本、图表、表格；避免整页栅格 | 文字可选、字体替换、尺寸；原生 Morph / 动画需要目标 PowerPoint 或 Keynote 实播 |

- 优先用 150–260ms 元素反馈与 250–450ms 对象延续作为起点，按读速校准。舞台揭示可更慢，但由主持触发。
- 用 transform / opacity 做常规移动；有明显前后状态时用同一对象的 Morph、Magic Move 或 FLIP。重新进入页时重置，跳页必须能直接读。
- 把动效设计成「起始态 → 触发 → 结束态 → 静态替代」。支持暂停、重播和减少动态；遮罩不能遮住必要正文。
- CSS/WAAPI 适合轻量局部；GSAP 适合多对象和时间线；Reveal.js / Slidev 负责网页演示逻辑；原生动画依赖演示软件版本。
- 舞台包连本地图片、字体、视频/音频许可、JSON、控台页面和启动说明一起交付。分开核验网页、PPTX 和 PDF。
