# Deck 审美规则（公开版）

> 用途：给生成 HTML 或 PPT 演示稿的 AI 当作「品味」规则文件。
> 来源：一位市场负责人在约 3 个月的真实改稿中写下的反馈，共约 1800 条，已去重。规则全部从中归纳而来。
> 每条规则后括号里的 n 是命中该规则的反馈条数（正则统计，只用来排序）。一次性的、只针对某个客户的修改已经剔除。
> 同一偏好前后变过的，按后来的版本执行，见「偏好变化」一节。
> 「典型反馈」是对原话的转述，不是引用。

---

## 0. 十五条总纲（按频次）

1. 先找参考：按给定的参考图、参考页或参考站点做，不要另外发明版式。（n=144）
2. 图像优先：复杂页面先出设计图，再用 HTML 按像素还原，还原度目标 90% 到 99%。（n=107）
3. 只用真实素材：官方 logo、真实截图、真实照片，全部要高清。（n=100）
4. 要有动效，但要慢、要淡，不能干扰阅读。（n=95 / 27）
5. 要有高级感：「丑」「low」本身就是打回的理由。（n=92）
6. 不挤、不溢出、不重叠、不遮挡。（n=71）
7. 屏与屏、页与页的衔接要自然，不能有断层。（n=66）
8. 同组元素等大、等距、对齐、居中。（n=63）
9. 字不能太小，演示场合最小 12pt。（n=60）
10. 能用图就不用字：少字，多用图示和 bullet。（n=58）
11. 留白要有节奏，板块间距全局统一。（n=57）
12. 用对比讲差异：传统做法用灰调，我方高亮。（n=53）
13. 控制行数：标题一到两行，指定不换行的地方绝不换行。（n=47）
14. 立体和扁平不能混用，一套 deck 只用一种质感。（n=47）
15. 禁止单字成行，一两个字落在最后一行也不行。（n=18，每次出现都是硬性打回）

## 1. 必须强调

**1.1 每组只强调一个关键短语或数字，放大加强调色，或者只加粗；同组内强调的位置保持一致。**（n=29）
- 测试：同组卡片的强调位置相同；每段最多一处强调。
- 典型反馈：这里的重点不明显，要突出；把核心能力词放大并用强调色。

**1.2 讲差异要靠对比结构：对照方用灰调，我方更亮、阴影更高。**（n=53）
- 测试：凡是做比较的页面，都有左右或上下的对照，两边明度一眼可分。

**1.3 主副标题必须是结论或观点，不能只是目录词。**（n=16）
- 测试：单独读每页主标题，应该是一句有判断的话。「两类方案」「三层服务」这类说法不合格。
- 典型反馈：看不出每个标题的观点是什么，要给出结论。

**1.4 数据要有咨询感：一句话把数据和观点放在一起做重点引用，按视觉优先级排版，用图表撑起专业感。**（n=8）

## 2. 不用管（可以省掉）

**2.1 数据来源、统计口径、样本说明这类脚注默认不放在页面上，需要时放进讲稿或附件。**（n=20）

**2.2 没有信息量的副标题、英文角标、装饰性 tag 直接去掉。**（n=17）

**2.3 讲解时口头会说的内容不写在页面上，页面不是逐字稿。**

**2.4 用户用不到的交互（进度条、选择计数等）不做。**

## 3. 一定要删

**3.1 黑边、白边、屏间色带断层和白色缺口要清掉。**（n=28）
- 测试：视频和动图上下没有黑带；滚动和切换时背景连续。

**3.2 多余的线条、分隔竖线、白框和边框都删，只留承担结构作用的线。**（n=22）
- 测试：每条线都要说得出用途，说不出就删。

**3.3 同一信息全 deck 只出现一次。**（n=21）

**3.4 废话、口号、车轱辘话和「正确的废话」都删。**（n=11）

**3.5 禁用「不是……而是……」句式，这个句式会被认为 AI 味重。**（n=7，明确禁令）

**3.6 「示意稿」「已脱敏」「非真实数据」「还没跑完」这类内部提示语不出现在对外页面上。**（n=7）

**3.7 不用 emoji，图标一律画成统一风格的 icon。**（明确禁令）

## 4. 字号与层级

**4.1 字号不能小到看不清。演示 deck 最小 12pt；大框里不能只放小字。**（n=60）
- 测试：在 1920×1080 画布上，正文 ≥ 24px，最小标注 ≥ 16px。

**4.2 主副标题全 deck 用同一模板，字号、颜色、位置都一致，翻页时标题不跳动。**（n=26）
- 测试：逐页量主副标题的 font-size 和 top 坐标，除封面和结束页外只允许一个值。

**4.3 字号比例要协调，不能大的巨大、小的太小，左右两侧的字号要平衡。**（n=39）
- 测试：同一页最大字号和正文字号之比 ≤ 3:1（封面例外）。

**4.4 主标题不超过两行，副标题尽量一行；指定「同一行」或「不换行」的地方必须照做，换行位置按给定的来。**（n=47）

**4.5 正文默认不加粗，只加粗一句关键句。**（n=14）

## 5. 配色

**5.1 三色体系：红、黑、米。内容页用米色或浅色底，黑色只用于封面、结束页和首屏；全 deck 只用一个主题色。**（n=26 / 16）
- 测试：除首尾页外，背景色是同一个值；强调色只有一个主红，外加一个淡红或粉作为辅助色。
- 页与页之间不能出现配色分裂（比如一页蓝粉、一页绿粉）。

**5.2 不能太红、太粉、太黑，对比不能刺眼。大面积色块不用纯红。**（n=14）

**5.3 不用黑底白字的大色块，也不用深黑或深红的底；需要强调的模块改用淡粉或浅色。**（n=17）

**5.4 收束句（如果保留）不用红字。**

**5.5 页面不跟随系统暗色模式，永远用设定好的配色。**

## 6. 排版网格

**6.1 不挤、不溢出、不重叠、不遮挡；文字和翻页控件之间要留出安全距离。**（n=71）
- 测试：文本节点的内容尺寸 ≤ 容器尺寸；元素的包围盒互不相交；底部内容和翻页控件之间 ≥ 24px。

**6.2 同组元素等大、等距、对齐；图标在圆心，圆要正圆，形状里的文字要在正中。**（n=63）
- 测试：同组卡片宽高相等，间距差 ≤ 2px。

**6.3 所有板块之间的间距统一，取一个认可的值作为全局标准。**（n=57）
- 测试：相邻板块的垂直间距只有一个取值（±8px）。

**6.4 画面要填满：不留没有用途的大块空白，信息密度不够时补图或补数据。**（n=8）

**6.5 禁止单字成行（一两个字落单也不行）。同组框里的文案行数相同、字数相近，强调位置统一。**（n=18）
- 测试：渲染后每个文本块的最后一行 ≥ 3 个字；同组框行数相同，每行字数差 ≤ 2。

**6.6 页眉固定：左上角放板块名（淡色小字），右上角放 logo，封面和结束页不放；logo 每页大小和位置一致。**（n=9）

## 7. 图文与证据

**7.1 只用真实素材：logo 用官方原版（彩色、透明底、无白边、不变形），截图和照片用真实的，图片要高清。**（n=100）
- 测试：没有用文字拼的假 logo；截图没有被裁掉一半；图片按显示尺寸的 2 倍提供。

**7.2 能画图就不写字：长段落改成 bullet 或短句 tag，概念用图示或图表来讲。**（n=58）
- 测试：每页正文 ≤ 80 个汉字（案例页 ≤ 120）；没有超过 3 行的段落。

**7.3 图示要有逻辑：一眼看得出阶段、循环和流向，不要把一段话硬画成图。**（n=11）

**7.4 案例页用固定三段式（痛点 / 解法 / 结果，或背景 / 卡点 / 结论，或 before 到 after），三段格式一致、长度相近。**（n=9）

**7.5 场景图：真实照片加黑色蒙版，再叠几句文字或数据点。**（n=10）

## 8. 动效与交互

**8.1 要有动效，完全静态会被认为「死」。**（n=95）

**8.2 动效要克制：字多的区域动画要慢、要淡，入场用淡入，不要跳脱。**（n=27）
- 测试：入场时长在 400ms 到 1200ms 之间；正文背后没有持续循环的高对比动画；支持 prefers-reduced-motion。

**8.3 卡片初始状态等大，悬停时再突出；不做一直在转的装饰物。**（n=11）

**8.4 屏与屏之间原地转换、自然衔接；用叠卡滚动时，下一张要完全盖住上一张，再整体往下走。**（n=66）

**8.5 视频高清、自动播放、无缝循环，不显示播放键；视频底色和页面背景完全一致。**

**8.6 会滚动的数字用等宽数字（tabular-nums）。**

## 9. 手机端

**9.1 网页类交付默认要做手机端适配，并在多种屏幕尺寸下自检多轮。**（n=34）
- 测试：在 375、390、430 三种宽度下没有横向滚动，字号、留白和动画的逻辑与桌面端一致。

**9.2 手机端板块间留白统一，字号整体调和；长句拆成上下两行并放大；logo 缩小到桌面端的 70% 左右。**

**9.3 手机端滑动时不能有白色断层或色块抖动，控件不能挡住视觉。**

## 10. 文案口吻

**10.1 说人话：不要 AI 味、翻译腔和行业黑话，客户听不懂的词都改掉。**（n=22）

**10.2 主副标题连起来要能读成一个完整故事，页与页之间要有承接。**（n=34）

**10.3 文案要 sharp：直戳痛点、和业务相关，写清 AI 让事情具体快了多少、准了多少。**

**10.4 标题和短句去掉句号；正文少用破折号；中文与数字、英文之间留空格。**（n=13）

**10.5 文案定稿前，交给另一个文本模型做一轮「简洁、去废话」的打磨。**（n=16）

## 11. 改稿工作方式

**11.1 以参考为驱动：给了参考图、参考页或参考站点，就按它的版式和感觉做。**（n=144）

**11.2 图像优先的像素还原：复杂页先让图像模型出设计图，再用 HTML 还原 90% 到 99%。验收方式是固定 1920×1080 画布、截图叠图和 pixel diff。**（n=107）

**11.3 按指定轮数迭代（常见 3、5、8 到 10、20 轮），每轮都截图自检，不要做一轮就交。**（n=25）

**11.4 还原轮的保护原则：没有设计图的页不动；对话里已经改定的主副标题不动；页码和 logo 位置不动；主副标题的字号和背景色保持当前值。**

**11.5 先文字后动手：涉及文案、结构或叙事的修改，先在对话里给出文字方案，确认后再改文件或部署。**（n=33）

**11.6 复用源代码和模板：迁移已有页面时整页搬源代码，样式和当前模板对齐，不能塞截图。**（n=33）

**11.7 改坏就回退：收到「恢复」「改回」时回到上一版的具体状态，只保留点名要留的改动。**（n=23）

**11.8 默认公开部署，不加访问码；更新时不覆盖旧链接，新版本推到新地址。**（n=10）

**11.9 送审用截图表：协作文档里放三列「板块 / 截图 / 备注」，逐页截图供批注。**（n=10）

**11.10 反馈是编号清单时，逐条改、逐条核对，交付时说明每一项的处理结果。**

**11.11 支持坐标批注：「图 1：(x%, y%) 说明」这种格式要先定位到元素再改。**（n=8）

## 偏好变化（执行后来的版本）

| 话题 | 早期 | 后来（执行这个） |
|---|---|---|
| 页面底色 | 全黑背景 | 全黑会造成视觉疲劳；内容页用米色，黑色只用于首尾页和首屏 |
| 收束句 | 红色竖条加深色粗体 | 默认不放收束句；如果保留，用深色粗体，不用红色 |
| 关键词强调 | 放大加强调色 | 每段最多一处；正文整体不加粗；放大加强调色只给核心数字 |
| 线条 | 去掉线条框架感 | 方框和格子线去掉，细而顺的科技感曲线可以用 |
| 立体还是透明 | 同一天里在立体和透明之间反复 | 一套 deck 只用一种深度语言，选定后统一 |
| 左上角板块名 | 去掉 | 保留，用淡色小字 |
| 页码 | 去掉 | 保留，字号要够大 |
| 动效强度 | 越动态越好 | 要有动效，但要慢、要淡，正文区域要安静 |
