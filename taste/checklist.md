# Deck 渲染验收清单（30 项）

用法：在 1920×1080 固定画布上逐页截图，网页类交付还要在 375、390、430 三种宽度下各截一遍，然后对照下表逐条判 PASS 或 FAIL。只要有一项 FAIL，就不能交付。括号里是对应的规则编号（见 taste.md）。

## 文字与层级
1. 所有文本块的最后一行都 ≥ 3 个字（没有单字成行，也没有两字成行）。（6.5）
2. 同组卡片里的文案行数相同，每行字数差 ≤ 2。（6.5）
3. 正文 ≥ 24px，最小标注 ≥ 16px（12pt）；大框里没有只放小字的情况。（4.1）
4. 除封面和结束页外，各页主标题的 font-size、颜色和 top 坐标都相同。（4.2）
5. 除封面和结束页外，各页副标题的 font-size、颜色和 top 坐标都相同。（4.2）
6. 同一页里最大字号和正文字号之比 ≤ 3:1（封面例外），左右两栏的正文字号相同。（4.3）
7. 主标题 ≤ 2 行，副标题 ≤ 2 行（尽量 1 行）。（4.4）
8. 每段最多一处强调；正文没有整段加粗；同组的强调位置一致。（1.1, 4.5）

## 排版网格
9. 没有文字溢出容器（文本内容尺寸 ≤ 容器尺寸），元素之间没有重叠或遮挡。（6.1）
10. 底部内容和翻页控件之间 ≥ 24px。（6.1）
11. 同组卡片宽高相等，间距差 ≤ 2px；图标在圆心；圆是正圆。（6.2）
12. 相邻板块之间的垂直间距只有一个取值（±8px）。（6.3）
13. 页面上没有没有用途的大块空白（超过画面 15% 的空区域要有理由）。（6.4）
14. 除首尾页外，左上角都是同一种板块名样式，右上角都是同一个 logo，大小和位置每页一致。（6.6）

## 配色与质感
15. 除首尾页和首屏外，背景是同一个米色或浅色值。（5.1）
16. 全 deck 只用一个主强调色（另加一个淡色辅助色），没有页与页之间配色分裂。（5.1）
17. 没有大面积纯红色块，也没有深黑或深红的底配白字的大模块。（5.2, 5.3）
18. 每条线都有结构用途；没有装饰性白框、格子线和多余竖线。（3.2）
19. 全 deck 只用一种深度语言（都立体或都扁平），阴影强度一致。（第 0 节第 14 条）
20. 没有黑边、白边和屏间色带；视频底色和页面背景一致。（3.1, 8.5）

## 图文与证据
21. logo 都是官方原版，透明底、无白边、无变形；截图没有被裁残；图片清晰不糊。（7.1）
22. 每页正文 ≤ 80 个汉字（案例页 ≤ 120），没有超过 3 行的段落。（7.2）
23. 案例页三段式的格式一致，三段的长度相近。（7.4）
24. 页面上没有数据来源、口径说明、「示意稿」「已脱敏」之类的内部提示，也没有 emoji。（2.1, 3.6, 3.7）

## 文案
25. 每页主标题都是一句有判断的话，不是目录词；把所有主标题连起来读，是一个连续的故事。（1.3, 10.2）
26. 全文没有「不是……而是……」句式，没有口号式的空话，同一信息只出现一次。（3.3 至 3.5）
27. 标题没有句号；中文和数字、英文之间有空格。（10.4）

## 动效与手机端
28. 页面有动效；入场时长在 400ms 到 1200ms；正文背后没有高对比的循环动画；支持 prefers-reduced-motion。（8.1, 8.2）
29. 视频自动播放、循环，不显示播放键；会滚动的数字用 tabular-nums。（8.5, 8.6）
30. 在 375、390、430 三种宽度下都没有横向滚动，没有白色断层，板块间距统一，第 1、3、9 项同样通过。（9.1 至 9.3）
