# Amber Deck Skill

Make the story legible before making it beautiful. Use a clear thesis, one visual focal point per slide, and evidence that makes the thesis believable.

1. **Lock the assignment.** Record the audience, what they need to decide, speaker vs. self-read, requested format and slide count, required brand references and proof. Preserve the source framework and approved claims. Put missing evidence in a review list; do not invent metrics, client quotes, endorsements or dates.
2. **Find the closest reference.** Inspect a supplied deck or screenshot at slide size. With a private vault available, use [the local-vault workflow](references/local-vault.md) to locate 1–2 projects and a specific page or component. Otherwise use [art direction](references/art-direction.md) or the synthetic demo. Select one direction that fits the occasion.
3. **Design a slide contract.** Use [the storyboard schema](references/storyboard.md) to record each slide's purpose, headline, proof, composition, and motion cue. Prototype an opening, evidence, and decision slide before propagating the visual rules.
4. **Choose output by delivery.** For editable PowerPoint, use an installed PPTX workflow and native text, charts, tables and diagrams; use imagery as separate assets. For browser or stage, use HTML with deliberate navigation and offline assets. For pixel restoration, measure reference geometry; compare overlays while preserving the requested level of editability. See [format and motion routing](references/motion-and-output.md).
5. **Finish with the actual artifact.** Render every slide at target aspect ratio. Review a contact sheet for rhythm, then slides at reading size for evidence, line breaks, legibility, alignment, image treatment and overflow. Test navigation, video and fallback for live HTML. Export static backup when needed. Use [the review checklist](references/review.md). Report unresolved evidence as review notes.

Use [effect recipes](references/effect-recipes.md) when a layout or transition has a job. Use [the GitHub index](references/github-index.md) to choose a tool; review upstream code, license and dependencies before installation. The bundled demo is a working reference, not a required template.

Only copy company and client elements the user is entitled to reuse. Recheck names, numbers, claims, imagery, URLs, QR codes, audio and font rights for the intended audience. Access to an original does not grant publication rights.
